# Skill: Root Cause Analysis

## Purpose
Identify the underlying root cause of a bug, backed by evidence.

## When to use
After bug investigation and repository research, for bug-type work items.

## Expected inputs
- Symptom description, reproduction evidence, relevant code and logs.

## Expected outputs
- A stated root cause with supporting evidence, contributing factors, and a confidence level.

## Important rules
- The root cause must cite evidence, not speculation.
- Distinguish the root cause from merely contributing factors.
- Assign an explicit confidence level (unknown/low/medium/high).

## Failure / uncertainty
- If a defensible root cause cannot be established, record the strongest hypothesis as an assumption and expose remaining unknowns, rather than asserting certainty.
