# Skill: Repository Research

## Purpose
Inspect source code to ground the work item in the actual codebase.

## When to use
After documentation research, when code-level understanding is required.

## Expected inputs
- Repository access, relevant file paths, key symbols, ticket context.

## Expected outputs
- Relevant code excerpts, file paths, and a summary of module behavior.

## Important rules
- Read-only.
- Never modify, commit, or create pull requests.
- Cite file paths and line numbers for every claim.

## Failure / uncertainty
- If the relevant code cannot be located, record this as an unknown and flag the need for clarification.
