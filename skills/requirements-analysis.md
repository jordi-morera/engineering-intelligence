# Skill: Requirements Analysis

## Purpose
Derive clear, testable requirements from a work item and its research context.

## When to use
After ticket analysis and research, when defining what must be built.

## Expected inputs
- Ticket objective, research findings, technical context.

## Expected outputs
- A set of functional and non-functional requirements, each with acceptance criteria.

## Important rules
- Requirements must be testable, not vague aspirations.
- Distinguish hard requirements from nice-to-haves.
- Record assumptions that underpin each requirement.

## Failure / uncertainty
- If a requirement cannot be stated testably, flag it as an open question or blocked item.
