# Skill: Technical Analysis

## Purpose
Assess feasibility, constraints, dependencies, and risks of a proposed change.

## When to use
After requirements are defined, before producing a specification.

## Expected inputs
- Requirements, researched technical context, architecture constraints.

## Expected outputs
- A technical assessment: feasibility, constraints, dependencies, and risks.

## Important rules
- Ground conclusions in the researched code and documentation.
- Distinguish observed constraints from assumed ones.
- Be explicit about performance, security, and backward-compatibility impacts.

## Failure / uncertainty
- If the technical basis is insufficient, record the missing evidence rather than guessing.
